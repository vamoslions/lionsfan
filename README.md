# 🦁 VAMOS LIONS — 삼성 라이온즈 팬 허브

삼성 라이온즈 팬을 위한 비공식 팬 사이트입니다. 2026 한국시리즈 **V9 우승**을 기록하고,
다음 목표인 **V10**을 추적하는 두 가지 뷰를 제공합니다.

- **`index.html`** — 사이드바 + 위젯 그리드의 **LIONS 대시보드** (메인)
- **`magazine.html`** — 스크롤형 롱폼 **팬 매거진** (기존 버전)

두 페이지는 같은 `js/data.js`와 `localStorage` 키(`lions-theme`, `vamos-lions-cheers-v1`, `vamos-lions-squad-v1`)를 공유합니다.
테마나 매거진의 팬 보드에 남긴 응원, 나만의 스쿼드가 페이지를 오가도 유지됩니다.

> 비공식 팬 프로젝트입니다. 삼성 라이온즈 / KBO와 제휴 관계가 없으며, 구단 공식 로고·공식 선수 사진은 사용하지 않았습니다.
> 선수 카드는 사용 권한과 이름이 확인된 **공식/제공 프로필 사진**만 허용합니다. 현재 해당 사진이 없어 28명 모두 기본 실루엣을 표시합니다. 기존 Commons 사진 7장은 보관 자료이며 카드에 사용하지 않습니다.
> 기록과 일정은 2026 포스트시즌 · 2026-11-15 기준이며, 새 시즌 정보는 `js/data.js`에서 업데이트할 수 있습니다.
> 인스타그램은 2026-11-20 직접 프로필을 확인한 15명만 연결했고, 확인되지 않은 선수는 `계정 정보 없음`으로 표시합니다.

## 현재 데이터 흐름

- `index.html`: 대시보드. 기존에는 우승 히어로 → FA/뉴스 → 일정/기록 → 선수/스쿼드 → 팬보드 순서였으며, 이제 **다음 경기·최근 결과·팬 응원 요약과 주요 메뉴**가 먼저 나옵니다.
- `magazine.html`: 홈페이지/롱폼. 기존 히어로·일정·선수·코치·우승 연혁·TV·SNS·직관 가이드는 유지하고, 요약·팬보드·뉴스/FA를 앞에 묶었습니다.
- 팬보드: 기존 대시보드의 GitHub Issues와 홈페이지의 localStorage가 달랐으나, 이제 `js/fanboard.js` 하나가 양쪽의 글을 관리합니다.
- 선수 프로필: `js/data.js`의 `playerProfiles` 맵만 사용합니다. 이름 일치(`verifiedName`)와 사용 권한 확인 후 `src`, `source`, 선택 `objectPosition`을 등록합니다.
- 뉴스/FA: 기존 `data.js`의 수동 `news`/`fa`는 이전 기록으로 남겨 두되 **화면에서는 사용하지 않습니다.** `data/news.json`, `data/fa.json`과 `js/live-data.js`를 사용합니다.

### 예약 데이터 갱신 (GitHub Actions)

워크플로: `.github/workflows/refresh-pages.yml`. 수집 → 단위 테스트 → Pages 배포를 방문자 없이 실행합니다.

| 항목 | 공식/제공 출처 | 예약 (KST) |
| --- | --- | --- |
| 뉴스 | [연합뉴스 스포츠 RSS](https://www.yna.co.kr/rss/sports.xml)에서 삼성 관련 기사 제목·매체·발행일·원문 URL만 수집 | 매시 17분 (60분 간격) |
| FA | [KBO 보도자료](https://www.koreabaseball.com/MediaNews/Notice/List.aspx), [삼성 공식 구단소식](https://www.samsunglions.com/intro/intro02.asp) | 09:47 / 21:47 |

- 뉴스 기본 요구 30분 대신 RSS의 `sy:updatePeriod=hourly`에 맞춰 60분으로 조정했습니다. 본문·기사 사진은 재게시하지 않습니다.
- Google News RSS는 개인 피드 리더 용도 제한이 명시되어 있어 이 공개 사이트의 데이터원으로 사용하지 않습니다.
- 외부 API 키/유료 서비스 불필요. Actions가 제공하는 `GITHUB_TOKEN`과 Pages OIDC만 사용합니다.
- 저장소 **Settings → Pages → Source: GitHub Actions**, Actions 허용, 기본 브랜치 `main`이 필요합니다. 예약은 GitHub 사정에 따라 지연될 수 있으며 비활성 공개 저장소는 60일 뒤 예약이 중단될 수 있습니다.
- 뉴스는 URL의 추적 파라미터와 정규화된 제목으로 중복 제거 후 최신순입니다.
- FA 시장 연도는 한국시간 11~12월이면 다음 시즌, 1~10월이면 해당 시즌입니다. 현재 공식 공시는 **2027 FA 시장**입니다.
- 공식 FA 승인 본문에서 삼성 선수 명단을 읽고, 실제 체결 문장이 확인된 구단 발표만 계약으로 반영합니다. 계약 추측·루머는 사용하지 않습니다.
- **범위 제한:** 구단 최근 공지 3페이지와 KBO 최근 보도자료를 확인합니다. KBO 선수 이동 AJAX는 현재 오류 응답을 반환하므로 사용하지 않습니다. 타 구단 공지만 있는 이적·모호한 문장은 확정하지 않고 미확인으로 유지합니다.
- `lastSuccessAt`은 성공 시에만 변경됩니다. 수집/파싱 실패 시 이전 JSON과 성공 시각을 그대로 보존하고 `data/status.json`에 실패를 기록합니다. 브라우저 연결 실패도 캐시를 유지합니다.
- 예약 배포는 소스 커밋을 만들지 않습니다. 다음 실행은 라이브 사이트의 더 최신 JSON을 복원한 뒤 수집하여 마지막 정상 데이터를 보존합니다.
- 수동 실행: Actions → **Refresh data and deploy Pages** → Run workflow (`all` / `news` / `fa`).

검증 명령:

```bash
pip install -r scripts/requirements.txt
python scripts/update_data.py --kind all
python -m unittest discover -s tests -p 'test_*.py'
# 별도 Playwright 설치와 로컬 서버 필요

```

### V10 표기 원칙

V10은 **아직 달성하지 않은 미래 목표**입니다. 그래서 V9과 다르게 표현했습니다.

- V10 숫자는 외곽선(ghost) 스타일, 별 10개 중 마지막 1개는 비어 있음
- 진행도는 `9 / 10`
- 캐비닛의 V10 칩은 점선 + `NEXT` 라벨
- 2027 개막일은 공식 일정이 아니므로 카운트다운과 카드에 **예상** 표시

## 데이터 업데이트

기록·일정·선수는 `js/data.js`에서, 자동 수집 뉴스·FA는 `data/*.json`에서 관리합니다.

- `schedule`: 경기 일정. `date`, `time`, `stage`, `opponent`, `home`, `venue`, `score`, `result`, `note`
- `roster`: 선수단. `name`, `group`(투수/포수/내야수/외야수), `role`, `tag`, `desc`, `emoji`, 선택 `photo`, 선택 `stat`, 선택 `squad`(퓨처스는 `"futures"`)
- `playerMeta`: 선수의 **확인된 수비 포지션**. `positions: ["CF", "LF"]` 형식이며, 확인되지 않은 포지션은 넣지 않습니다.
- `instagramAccounts`: 직접 확인한 인스타그램 계정. `handle`, `checkedAt`만 저장하고, 미확인 선수는 항목 자체를 만들지 않습니다.
- `instagramNotes`: 연결하지 않은 이유가 있는 선수의 메모. UI의 `계정 정보 없음` 툴팁에 사용됩니다.
- `simulation`: 예상 라인업, 실제 확인 기록 샘플, 리그 평균 가정값, 상대 팀 승률, 시뮬레이션 설정
  - `expectedLineup`: 공식 확정이 아닌 **팬 예상** 라인업
  - `batterSamples` / `pitcherSamples`: 확인된 기록만. `partial`은 포스트시즌 소표본
  - `priors`: 실제 2026 리그 평균이 아니라 **결측치 대체용 모델 사전확률**
  - `opponents`: 상대 팀 승률. 개별 선수 기록은 수집하지 않음
- `fa`, `news`: 이전 수동 입력 보관 자료. 현재 화면은 자동 수집 JSON 사용
- `stats`: 선수 기록. `featured`(OPS 스포트라이트), `mini`(세이브·ERA 등), `note`
- `photoCredits`: 선수 사진 출처. `name`, `author`, `license`, `period`, `href`
- `photoPolicy`: 사진 사용 원칙과 기본 아바타 설명
- `staff`: 감독·코칭스태프 (매거진)
- `timeline`: 우승 연혁 (V9까지)
- `standings`: 정규시즌 순위. `rank`, `team`, `short`, `wins`, `draws`, `losses`, `pct`
- `videos`: 라이온즈TV 콘텐츠 카드 (`query`가 유튜브 검색어로 연결됨)
- `links`: SNS/바로가기 링크
- `checklist`: 직관 가이드 카드 (매거진)
- `meta.nextSeasonOpener`: 카운트다운 기준일 (현재 2027-03-27 **예상일**)

새 경기를 추가할 때는 `schedule` 배열 맨 끝에 아래 형식으로 넣으면 됩니다.

```js
{
  date: "2027-03-27", time: "14:00", stage: "정규시즌 개막전",
  opponent: "롯데 자이언츠", home: true, venue: "대구 라이온즈파크",
  score: "-", result: "예정", note: "2027 개막전"
}
```

> `score`는 항상 **삼성 : 상대** 순서입니다. `result`가 `승`/`패`가 아니면 예정 경기로 표시됩니다.

### 선수 사진 · 기록

현재 `playerProfiles`는 비어 있으며, **모든 선수 카드에 3:4 기본 실루엣**을 표시합니다.
새 프로필은 공식 또는 프로젝트에 제공된 프로필인지, 사용 권한과 얼굴·선수 이름이 맞는지 확인한 뒤 등록하세요.

- 사용 중지한 보관 사진: 구자욱(2017), 강민호(2023), 최형우(2021 KIA 시절), 원태인(2025), 아리엘 후라도(2017 텍사스 시절), 크리스 페덱(2021 샌디에이고 시절), 김헌곤(2019). `roster.photo`는 카드에서 더 이상 읽지 않습니다.
- 사진이 없는 선수는 `assets/players/default.svg` **동일 기본 아바타**를 사용합니다. 임의 사진을 넣지 않습니다.
- 구단 공식 프로필 사진은 저작권상 직접 사용하지 않습니다. 공식 사진을 쓰려면 구단의 허락이 필요합니다.

`stat`을 추가하면 카드 우측에 작은 기록 배지가 붙습니다.

```js
{
  name: "구자욱", group: "외야수", role: "주장 · 외야수", tag: "2026 KS MVP",
  desc: "타율 .371로 리그 1위.", emoji: "🦁",
  stat: { label: "OPS", value: "1.039" },
  photo: "assets/players/koo.jpg"
}
```

### 퓨처스 명단

퓨처스 유망주는 `js/data.js`의 선수 객체에 `squad: "futures"`를 넣습니다.
선수단의 `퓨처스` 탭은 `squad === "futures"`인 선수만, `전체`·포지션 탭은 1군 선수만 보여줍니다.

```js
{
  name: "이창용", group: "내야수", role: "퓨처스 내야수", squad: "futures",
  tag: "퓨처스 OPS .901", desc: "2026 퓨처스리그에서 꾸준히 출전한 내야수.", emoji: "🦁",
  stat: { label: "OPS", value: ".901" }
}
```

현재 퓨처스 8명은 2026 퓨처스리그 실제 기록과 공식 로스터 포지션을 기준으로 정리했습니다.
시즌이 바뀌면 `tag`·`stat`·`desc`를 최신 기록으로 갱신해 주세요.

### 나만의 스쿼드

선발 투수 1명과 타자 9명을 골라 나만의 라인업을 만듭니다.

- **1~9번 타순**과 각 타순의 **수비 포지션**을 직접 지정합니다. 포지션을 바꾸면 빈 타순과 자동으로 자리를 맞바꿉니다.
- 투수는 **선발 투수** 슬롯에만, 야수는 **1~9번 타순** 슬롯에만 배치됩니다.
- 선수 카드에 확인된 포지션(`playerMeta.positions`)과 현재 타순 포지션을 비교해 `수비 적합` / `비주 포지션`을 표시합니다.
- 이미 넣은 선수를 다시 누르거나 슬롯의 `×`를 누르면 빠집니다. 같은 선수를 두 타순에 중복 배치할 수 없습니다.
- **다이아몬드 뷰**에서 포지션을 누르면 해당 타순이 선택됩니다.
- **예상 라인업** 버튼은 2026 한국시리즈 출전 조합 기반 팬 예상 라인업을 불러옵니다. 공식 확정 라인업이 아닙니다.
- 선택 내용은 브라우저 `localStorage`의 `vamos-lions-squad-v1` 키에 자동 저장되며, `저장` 버튼으로 저장 시각을 확인할 수 있습니다.
- `라인업 복사`는 선발·타순·포지션을 텍스트로 복사하고, `초기화`는 저장된 라인업을 지웁니다.
- 저장은 서버가 아닌 **현재 브라우저에만** 적용됩니다.

```js
// 저장 구조
{
  pitcher: "원태인",
  batters: ["김지찬", "김성윤", "구자욱", ...],
  positions: ["CF", "RF", "LF", "DH", "1B", "C", "3B", "SS", "2B"]
}
```

### AI 경기 시뮬레이션

`js/simulation.js`가 타석(PA) 단위로 경기를 반복 실행합니다.

- 사용자가 구성한 9명 타순 + 선발 투수 vs 선택한 상대 팀
- **10,000회** 기본 실행, 시드 고정으로 같은 조건이면 같은 결과 재현
- 9회·연장 3이닝까지 진행하고 무승부도 별도 집계
- 결과: 삼성/상대 승률, 무승부, 평균 득점, 예상 스코어, 스코어 분포, 핵심 선수 TOP 3, 타선 기여도, 선발 매치업, 핵심 변수, 추천 타순
- 추천 타순은 후보 5개를 각 320경기씩 비교합니다. 표본이 작아 **참고용**입니다.
- 실제 확인 기록: 구자욱 OBP/SLG, 최형우·박승규 포스트시즌 타율, 원태인·후라도·페덱 등의 포스트시즌 ERA
- 기록이 없는 타자·상대 선발은 `simulation.priors`의 **리그 평균 가정값**을 사용하며, 결과 화면에 실측/부분/대체 인원을 표시합니다.
- **수집하지 않아 시뮬레이션에 쓰지 않는 항목**: 최근 5·10경기 스플릿, 좌우 투수 상대 성적, 불펜 소모도, 상대 팀 개별 라인업·선수 기록, 홈/원정 세부 성적
- 2026시즌 종료로 **공식 다음 경기가 없습니다.** 따라서 현재는 2026 한국시리즈 기준 가상 매치업으로만 동작합니다.

> 시뮬레이션 결과는 통계적 추정치이며 실제 경기 결과를 보장하지 않습니다. 공식 예측·베팅 자료로 사용할 수 없습니다.

## 공유 팬 보드 (GitHub Issues)

`js/fanboard.js`가 브라우저 응원과 **GitHub Issues 공개 글**을 합쳐 두 페이지에 동일하게 공급합니다.

- 읽기: `https://api.github.com/repos/vamoslions/lionsfan/issues` 공개 API (CORS 허용, 비로그인 60회/시간)
- 필터: `fanboard` 라벨 **또는** 제목이 `[팬보드]`로 시작하는 열린 이슈만 표시
- 쓰기: 응원을 저장하면 같은 브라우저의 탭에 `storage` 이벤트로 즉시 반영됩니다. 이 글은 **이 브라우저에만 저장**되며 공개 글이 아닙니다.
- 공개: 저장한 글의 **GitHub에 공개/공개 ↗** → GitHub 로그인 → `Submit new issue`. 사이트는 약 1분마다 자동 확인합니다. 웹소켓 실시간 푸시가 아닙니다.
- 공개 글과 원래 브라우저 글의 고유 ID를 본문 마커로 연결하고 중복 제거합니다. 두 페이지 모두 최신 글부터 표시합니다.
- 탭들이 같은 요청 시각을 공유해 중복 조회를 줄이며, 숨겨진 탭은 조회하지 않습니다. API 제한 시 재시도 시간을 지키고 기존 글을 유지합니다.
- 캐시: 마지막으로 읽은 글은 `localStorage`(`vamos-lions-board-cache-v2`)에 저장되어 API가 막혀도 보입니다
- 데모: `index.html?board=demo` 로 열면 샘플 글 3개로 렌더링을 확인할 수 있습니다

모두에게 공개할 때만 GitHub 계정이 필요합니다. 공개 글 관리/삭제는 저장소 `Issues`에서 수행하며 다음 자동 확인에 반영됩니다. 사이트에 관리자 토큰을 넣지 않습니다.

## 배포 (GitHub Pages)

현재는 GitHub Actions가 데이터 갱신 후 정적 파일만 Pages 아티팩트로 배포합니다.
예약 갱신을 사용하려면 Pages Source는 **GitHub Actions**여야 합니다.

- 저장소: <https://github.com/vamoslions/lionsfan>
- 사이트: <https://vamoslions.github.io/lionsfan/>

```bash
# 최초 1회: 저장소를 만든 뒤
git remote add origin https://github.com/vamoslions/lionsfan.git
git push -u origin main
```

저장소 **Settings → Pages → Source: GitHub Actions**를 선택합니다.
파일을 수정하고 `git push`하면 수집·검증 후 배포됩니다. 예약 실행도 같은 워크플로를 사용합니다.

Netlify, Vercel, Cloudflare Pages에 폴더째 업로드해도 동일하게 동작합니다.
